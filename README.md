# Занос Токио — приложение и игра вдвоём

**Скачать приложение для Android:** вкладка **Releases** этого репозитория → `tokyo-drift.apk` (открыть на телефоне и установить). Каждая загрузка изменений в ветку `main` сама собирает новую версию.

## Как устроена игра вдвоём

У хоста стоит приложение, у друга приложения нет.

1. Хост раздаёт точку доступа (или оба подключены к одному Wi-Fi).
2. Хост: **ВДВОЁМ → Создать игру**. Телефон хоста становится маленьким сервером, на экране появляется QR.
3. Друг сканирует QR обычной камерой — игра открывается у него в браузере прямо с телефона хоста. Интернет не нужен.
4. Оба жмут **Поехали** → гараж → **В город**.

Город у всех одинаковый. Видно машины друг друга (с фарами, неоном, дымом и следами шин), метку P1/P2 над машиной, стрелку к другу, если он за краем экрана, точку на миникарте и на карте, счёт друга и пинг под миникартой. Машины мягко толкаются. Дрифт рядом с другом даёт бонус «близко!», как рядом с трафиком. Время суток берётся у хоста. Трафик, пешеходы и заезды у каждого свои.

Можно до 4 игроков.

## Сыграть уже сейчас, без приложения (через компьютер)

Нужен компьютер с [Node.js](https://nodejs.org) в той же сети, что и телефоны.

```
node server/server.js
```

В окне терминала появится QR и адрес вида `http://192.168.1.5:8080/?join=1`. Оба телефона сканируют QR и играют вместе. Компьютер тут просто раздаёт игру и пересылает сообщения.

## Что в папке

| Путь | Что это |
|---|---|
| `www/index.html` | сама игра (один файл, работает офлайн) |
| `server/` | сервер на Node.js — для игры через компьютер и для проверки |
| `native/android/` | встроенный сервер для Android (Java) и `MainActivity` |
| `native/ios/` | встроенный сервер для iPhone (Swift) и `MainViewController` |
| `scripts/` | скрипты, которые кладут нативные файлы в проекты Android / iOS |
| `.github/workflows/android.yml` | сборка APK в облаке GitHub, результат — в Releases |
| `assets/` | иконка и заставка приложения |
| `keys/debug.keystore` | ключ подписи тестовой сборки (чтобы обновления ставились поверх) |

## Android: APK без установки чего-либо (через GitHub)

1. Создайте репозиторий на GitHub и загрузите в него содержимое этой папки (вместе со скрытой папкой `.github`).
2. Вкладка **Actions** → **Android APK** → **Run workflow**.
3. Через 5–10 минут в готовом запуске скачайте архив **tokyo-drift-apk**, внутри — `app-debug.apk`.
4. Перекиньте APK на телефон и установите (Android попросит разрешить установку из этого источника).

## Android: через Android Studio

Нужны Node.js 20+ и Android Studio.

```
npm install
npm run android        # = npx cap add android + плагин + sync
npx cap open android   # откроется Android Studio → кнопка Run
```

## iPhone (нужен Mac с Xcode)

```
npm install
npm run ios            # = npx cap add ios + плагин + sync
npx cap open ios
```

В Xcode перетащите `ios/App/App/LocalServerPlugin.swift` и `ios/App/App/MainViewController.swift` в группу **App** (галочка Target: App), выберите свою команду в **Signing & Capabilities** и нажмите Run. Без платного аккаунта Apple Developer приложение работает на своём телефоне 7 дней, потом его нужно установить заново.

При первом создании игры iPhone спросит доступ к локальной сети — нужно разрешить.

## После изменения игры

Скопируйте новый `index.html` в `www/` и выполните `npx cap sync`.

## Если не подключается

- Телефоны должны быть в одной сети: друг подключён к точке доступа хоста (или оба к одному Wi-Fi). В некоторых публичных Wi-Fi устройства друг друга не видят — тогда только точка доступа.
- Если адресов несколько, нажмите на адрес под QR, чтобы переключить его.
- Хост не должен сворачивать приложение: на iPhone свёрнутое приложение перестаёт раздавать игру.
- В браузере друга на iPhone недоступно управление наклоном (Safari даёт датчики только по https) — остальное работает.
- Прогресс друга (монеты, машины) хранится в его браузере и привязан к адресу хоста — если адрес поменяется, он начнёт заново.

## Протокол (для разработчиков)

`GET /` — игра, `GET /info` — `{"ips":[...],"port":8080,"players":N}`, `WS /ws` — пересылка JSON-сообщений. Сервер присылает `welcome{id,host,peers}`, `join{id}`, `leave{id}`, `host{}`, `full{}`, `pong{ts}`; к остальным сообщениям добавляет `f` (id отправителя) и рассылает всем, кроме отправителя (или только `to`). В приложении игра хоста — игрок 1 и общается с сервером через плагин `LocalServer` (`start`, `send`, `stop`, событие `msg`).
